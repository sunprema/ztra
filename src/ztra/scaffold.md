`ztra init`'s implementation: writes a small, deliberately *working* starter project (three commented world YAML files plus a protocol that actually compiles against them) rather than empty templates, on the theory that a new user should start by editing something that already runs, not by filling in a blank page. The YAML bodies are heavily commented in place, doubling as inline documentation — pointing at `docs/WORLD_MODEL.md` and the exact next commands to run.

`scaffold()` refuses to overwrite anything that already exists (rather than silently merging or clobbering), listing every conflicting path in one `ScaffoldError` so a user can decide whether to clean up or point `init` at an empty directory. `NEXT_STEPS`, returned alongside the created file list, is the same "what to do now" text the CLI's `ztra init` output surfaces to the caller — kept here rather than in `cli.py` so the MCP server or any other caller gets the same guidance.
