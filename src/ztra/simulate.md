The simulator is the compiler's abstract-interpretation engine run a second way: instead of just checking whether a protocol is legal, it plays each path forward and records what every sensor would read along it. The "nominal" run — no noise at all — is the prediction the rest of the system treats as ground truth; a batch of seeded noisy runs on top of that says how much to trust it.

`Noise` is a small, honest knob: everything defaults off, and `Noise.normal()` (pipette accuracy on, nothing else) is what a healthy robot actually looks like. The other fields — `dispense_drift`, `jitter_ul`, `failure_rate` — exist for stress-testing a protocol against a robot that isn't behaving, not for everyday use.

`simulate()` iterates the compiler's `paths(pir)` (one per branch outcome), runs `_run()` once nominally and then once per seed with an independent `random.Random`, and folds the seeded readings into a mean/std per metric (`ReadingStats`). That spread, combined with the sensor's own noise sigma, is what the diff engine later uses to decide whether an observed reading is a real deviation or just expected scatter.

`_run()` itself is a straight-line interpreter over `Transform`/`ObserveOp`, mirroring what the compiler already validated: it skips delays and tip-scope bookkeeping (nothing physically moves), engages/disengages the magnet, drains a tip rack on `replenish`, and flips a vial's thermal state on `thaw`. The one place noise actually enters is `_transfer()`: a run can fail outright (`failure_rate`), lose volume to drift and jitter, and layer in a per-run systematic pipette bias (`run.bias`, drawn once per pipette per seeded run so a single "off" pipette behaves consistently across all its dispenses in that run) plus per-dispense random error from the pipette's own accuracy spec. Overflow is handled by scaling down the liquid actually deposited, not by erroring — the world model has to end up in *some* consistent state even when the plan asked for more than a well could hold.

`nominal_world()` and `expected_readings()` are thin wrappers the store uses when it doesn't need the full seeded distribution — just "what would this protocol produce with nothing going wrong."
