The Store is ztra's "Vertical Git" — an append-only, hash-chained history of what an agent planned versus what actually happened in the lab. It borrows git's vocabulary (commit, branch, head, rebase) deliberately, but the semantics are physical, not textual: a merge would mean two independent robot runs converged into one plate, which makes no sense, so there is no merge at all.

Two commit kinds sit on top of the root: an `Intent` (a compiled protocol plus its predicted outcome(s), allowed on any branch) and an `Observation` (what telemetry actually showed, allowed only on `main`). Every commit and world snapshot is content-addressed — a JSON file named by its own SHA-256 under `.ztra/objects/`, so `_write` can be a no-op if the hash already exists. `verify()` walks every branch and recomputes those hashes to catch anything edited after the fact.

The two invariants that make this store useful for a physical system:

- **Execute is fast-forward only.** `execute()` refuses (`S_NOT_FAST_FORWARD`) unless the branch's head sits directly on top of `main`'s current head — because "reality moved on" underneath a stale branch is not something you can 3-way-merge away. The fix is `rebase()`, which recompiles every intent on the branch against the new `main`, letting real conflicts (a consumed reagent, a full tip rack) surface as ordinary `CompileError`s rather than silent drift.
- **You cannot plan past an unresolved reading.** If the head intent branches on an `Observe` with multiple possible outcomes, `working_world()` refuses (`S_UNRESOLVED`) until that intent is executed and the diff engine (or a caller) says which outcome happened. This is what keeps the DAG from growing hypothetical branches on top of hypothetical branches.

`execute()` has two paths: with telemetry, it recompiles and resimulates the intent (`_replay`), asks the diff engine which predicted outcome the readings match, and estimates the observed world from the deltas; without telemetry, the caller just states which outcome happened and that prediction stands in as reality. `execute_aborted()` is the same idea for a run that stopped partway — the observed world is whatever the completed steps alone would have produced, and the intent still counts as executed (retrying means rebasing a new intent on top, not replaying the same one).
