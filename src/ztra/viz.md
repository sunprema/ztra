Zero-dependency visualization for notebooks: every function returns inline SVG or HTML strings, and a `World`/`WorldDiff` shows these automatically in Jupyter via `_repr_html_`. This exists so a person (or an agent narrating its own work) can *see* the bench without installing a plotting stack — matplotlib, plotly, etc. are all more than this needs.

The pieces compose upward: `plate_svg`/`tip_rack_svg`/`deck_svg`/`vials_html` each draw one part of the bench (a filled well grows a colored circle sized by volume; a reservoir draws as troughs filling from the bottom; a used tip is a hollow dot); `world_html` lays all of them out on one card. `diff_html` does the analogous thing for a `WorldDiff` — a table of predicted/observed/delta/verdict per reading, plus, when given the world, plates re-colored by verdict instead of contents (`_verdict_plate_svg`) so a deviation is visible spatially, not just in a table row.

The more interesting piece is `trace`/`animate_html`: `trace` replays a protocol with an *accurate* `FakeDriver` (ideal pipettes — this is about showing what should happen, not stress-testing) one lowered op at a time, capturing a `Frame` (a full world snapshot plus a plain-English description via `describe_op`) after every op. `animate_html` renders all frames into one self-contained div with a scrubber and a play button — pure inline `<script>`, no framework — so a whole protocol run can be scrubbed like film in a notebook cell. A static renderer (e.g. GitHub's notebook viewer) just shows the last frame, which is deliberately the fully-executed end state.
